Keeping secrets out of images and logs during self-hosted deploys

Managed platforms handle secrets in a vault you never see. On your own server, you decide where they live.

Do not bake secrets into images

Anything in a Dockerfile ENV or ARG ends up in image history. Anyone who can pull the image can read it.

docker history --no-trunc myimage | grep -i key

If that finds something, rotate the key.

Use runtime variables

Pass secrets when the container starts, from the platform's environment settings or Docker secrets mounted as files. Read files in the app where possible.

Build time secrets

Use BuildKit secret mounts so the value is available during one build step and not stored:

RUN --mount=type=secret,id=npmrc cat /run/secrets/npmrc > ~/.npmrc && npm ci

Logs

Applications often log configuration at startup. Mask tokens. Also check that error pages do not dump environment variables.

Rotation

Know how to rotate each secret and how long it takes. Practice once. secrets management for a self-hosted PaaS is a platform that keeps environment values with each project on your server.
