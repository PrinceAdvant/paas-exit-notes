Git push deploys: webhooks or CI as the trigger

Heroku trained us to push and have the app deploy. On your own server there are two sensible ways to get that flow back.

Option one: a webhook

GitHub calls a URL on your platform when you push. The platform pulls the code, builds the image and swaps containers. It is simple and fast to set up, and it deploys whatever is pushed, even code that fails tests, unless the branch is protected.

Option two: CI triggers deploy

CI runs tests, builds an image, pushes it to a registry, and then calls the platform to deploy that exact image. You get gating on test results and reproducible images, at the cost of a registry and more setup.

Which to choose

For personal projects and early products, webhooks. For teams with tests that matter, CI first.

Security

Verify the webhook secret, keep the deploy endpoint non guessable and limit the deploy key to read only access on one repository.

Rollback

Keep the last few images so you can redeploy a previous tag in seconds. See Git-based deployment on a self-hosted PaaS for a platform that wires Git to containers on your own hardware.

Two ways to start a deploy and the tradeoffs of each.
