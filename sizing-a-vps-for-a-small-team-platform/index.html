Sizing a VPS for a small team platform

Choosing a server size by guessing leads to overpaying or to random container kills. A short calculation is better.

Count memory first

Memory is usually the limit. Typical resident sizes: a Node API 150 to 300 MB, a Rails app 300 to 500 MB, Postgres 200 MB plus cache, Redis 50 MB, a Next.js server 200 to 400 MB. The platform and proxy need another 500 MB.

Add headroom

Plan for 70 percent usage at steady state. Builds are bursty. Compiling a JavaScript project can need 1.5 GB, so build elsewhere or add swap.

CPU

Most small apps are idle. Two vCPUs handle many projects. Look for sustained load above one per core.

Disk

Docker images and layers accumulate. Allow 40 GB for the system and images, plus data. Run docker system df monthly and prune unused images.

Example

Five small apps, a Postgres and a Redis: about 3.5 GB in use. An 8 GB machine gives breathing room for builds.

Revisit

Check after a month with real data. Downsizing is as easy as upsizing at most providers. server sizing for a self-hosted PaaS lists this kind of guidance alongside a platform for such servers.
