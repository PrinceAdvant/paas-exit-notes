Replacing Heroku Scheduler with cron in a container world

Heroku Scheduler ran commands every ten minutes, hour or day. On your own server you have more choices and a few new ways to get it wrong.

Option 1: host cron calling docker

0 3 * * * docker exec app python manage.py cleanup

Simple. It depends on the container being up and has no overlap protection.

Option 2: a scheduler container

A small container running supercronic with a crontab file in the repository. Schedules live in Git and logs go to standard output where Docker captures them.

Option 3: the app's own scheduler

Celery beat, Sidekiq cron or similar. Needs exactly one scheduler process or jobs run twice.

Reliability tips

  • Use flock to prevent overlap on long jobs.
  • Make jobs idempotent. A job that runs twice should not double charge a customer.
  • Alert when a job has not succeeded recently, with a heartbeat URL ping at the end.
  • Set time zones explicitly, usually UTC.

Choose

For few jobs, option 2. For a framework with built in scheduling, option 3. A platform overview for context is in scheduled jobs on a self-hosted PaaS.
