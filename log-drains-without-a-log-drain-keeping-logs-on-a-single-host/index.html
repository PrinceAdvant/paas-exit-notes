Log drains without a log drain: keeping logs on a single host

Heroku collected logs from every dyno and drained them to a service. Containers on your own server give you the raw pieces to rebuild this.

Write to standard output

Applications should log to stdout and stderr. Docker captures it. Avoid log files inside containers.

Limit growth

{
  "log-driver": "local",
  "log-opts": { "max-size": "20m", "max-file": "5" }
}

Put this in /etc/docker/daemon.json and restart Docker. The local driver is more compact than the default JSON driver.

Search

For quick questions: docker logs --since 1h app | grep ERROR. For history across containers, ship logs to Loki with a Promtail or Alloy agent, or to a hosted service with a free tier.

Structure

JSON logs with request ids make searching reliable. Pass a request id through the proxy and into the app.

Retention and privacy

Decide how long to keep logs and scrub personal data. Debug logs in production are a common privacy problem.

For an overview of the platform around this, see logs on a self-hosted PaaS.
